# Environment for the Sec. 8 (Nav2) experiments

The third-party stack is **not vendored**. It is installed from the ROS 2 Jazzy
apt repository; this file pins what was run and lists every departure from the
stack's defaults.

| component | version |
|---|---|
| OS | Ubuntu 24.04 (WSL2) |
| ROS 2 | Jazzy Jalisco |
| `nav2_controller`, `nav2_regulated_pure_pursuit_controller` | Jazzy distribution binaries |
| `nav2_graceful_controller` | 1.3.12 |
| `nav2_loopback_sim` | Jazzy distribution binary |
| Python | 3.12 |

## What is changed, and what is not

No `nav2_*` package is rebuilt; controller, planner, costmap and lifecycle
manager are the distribution binaries. What differs from a default launch is
configuration and three documented plant variants, all generated by
`code/nav2/make_params.py`, which names each override beside the default it
replaces:

* **Controller switches.** Four switches that the regulated-pure-pursuit plugin
  declares `true` are turned off: `use_regulated_linear_velocity_scaling`,
  `use_cost_regulated_linear_velocity_scaling`, `use_rotate_to_heading`,
  `use_collision_detection`. The first two *are* the regulation, so what is
  measured is plain pure pursuit with regulation disabled.
  `max_robot_pose_search_dist` is pinned to 2.5 m (its default expression's
  value for the 5 m costmap used). The graceful controller runs with `beta = 0`
  except where Sec. 8.5 (Supplement S7) reports the fully default configuration.
* **Local costmap.** Reduced to one inflation layer with no sensor input, 5 x 5 m,
  `track_unknown_space: false`. That key was added after the original freq_iso
  block (2026-09-06) and before its re-run (2026-09-13); `d105` tests whether it
  changes the controller's behaviour.
* **Delay relay.** `delay_node` inserts the transport delay between plant and
  controller and logs the delay it applied on every run. Over all Nav2 blocks the
  applied delay exceeds the request by 0.0–1.8% at 0.1–0.8 s and by up to 3.4%
  at 0.05 s; per-point standard deviations are at most 0.9 ms except in one
  block (8 ms).
* **Plant variants.** `loopback_actuator` (first-order lag) and
  `loopback_bicycle` (Ackermann curvature saturation) each add one term to the
  shipped `nav2_loopback_sim` and reduce to it exactly when that term is zero —
  each block's own control row. `loopback_midpoint` changes the integrator's
  heading convention; it is a diagnostic, and no headline number rests on it.

## Reproducing a block

```bash
source /opt/ros/jazzy/setup.bash
source <workspace>/install/setup.bash
python3 code/nav2/experiment.py --block freq_iso --side 10 --laps 2.75 --npoints 17 --tau-inject 0.10
```

A block takes 1.5–4 h of wall clock. `d105` imports the harness from the
workspace (`~/letg2_ws/src/letg2_nav2_validation`) and launches its own stack.
